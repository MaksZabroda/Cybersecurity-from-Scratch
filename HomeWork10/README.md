# Домашнє завдання до уроків 9–10: Спрощений CIS checklist

## Опис

`cis_checklist.sh` — це навчальний Bash-скрипт для швидкої перевірки базових
налаштувань безпеки операційної системи.

Скрипт нічого не змінює в системі. Він лише читає доступні конфігураційні
файли та показує:

- які перевірки пройдено;
- які налаштування не відповідають checklist;
- які пункти неможливо перевірити автоматично;
- що можна зробити для виправлення знайдених проблем;
- команди, які допомагають виконати рекомендації.

> **Важливо:** це не офіційний CIS Benchmark і не замінює повний аудит
> безпеки. Це спрощена навчальна перевірка п’яти базових контролів.

## Підтримувані платформи

Скрипт автоматично визначає:

- Linux;
- macOS;
- WSL (Windows Subsystem for Linux).

Основна частина checklist орієнтована на Linux. Для macOS використовуються
доступні системні аналоги. У WSL окремо враховується, що частиною мережевої
безпеки та оновлень керує Windows.

## Що перевіряє скрипт

### 1. Мінімальна довжина пароля

Checklist вимагає мінімальну довжину пароля не менше восьми символів.

У Linux скрипт шукає параметр `minlen`:

- у `/etc/security/pwquality.conf`;
- у `/etc/security/pwquality.conf.d/*.conf`;
- у PAM-конфігурації біля модуля `pam_pwquality.so`.

Результат:

- `PASS`, якщо `minlen >= 8`;
- `FAIL`, якщо значення менше 8;
- `SKIP`, якщо параметр не заданий явно або конфігурація недоступна.

У macOS скрипт пробує прочитати `minChars` через `pwpolicy`. Нові версії
macOS можуть не показувати цей старий глобальний параметр, тому результатом
може бути `SKIP`. У такому разі політику потрібно перевірити через MDM або
configuration profile.

### 2. Фаєрвол

У Linux перевіряється стан UFW:

```bash
ufw status
```

Результат:

- `PASS`, якщо показано `Status: active`;
- `FAIL`, якщо UFW не встановлений або неактивний;
- `SKIP`, якщо стан неможливо прочитати без додаткових прав.

У macOS перевіряється Application Firewall через:

```bash
/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate
```

Для Fedora/RHEL типовим фаєрволом є `firewalld`. Скрипт надає команди для
його встановлення та запуску, але цей спрощений пункт безпосередньо перевіряє
саме UFW.

У WSL потрібно також перевіряти Windows Defender Firewall, оскільки основним
мережевим периметром керує Windows.

### 3. Заборона root-входу через SSH

Безпечне значення:

```text
PermitRootLogin no
```

Спочатку скрипт намагається отримати ефективну конфігурацію через `sshd -T`.
Якщо це неможливо, він читає:

- `/etc/ssh/sshd_config`;
- `/etc/ssh/sshd_config.d/*.conf`.

Результат:

- `PASS`, якщо встановлено `PermitRootLogin no`;
- `FAIL`, якщо root-вхід дозволено або значення `no` не задано явно;
- `PASS`, якщо SSH-сервер узагалі не встановлений.

### 4. Автоматичні оновлення

У Debian та Ubuntu перевіряється параметр:

```text
APT::Periodic::Unattended-Upgrade "1"
```

Для інших Linux-систем скрипт також розпізнає:

- `dnf-automatic.timer` у Fedora/RHEL;
- `yum-cron` зі значенням `apply_updates=yes` у старіших системах.

У macOS перевіряється системний параметр `AutomaticCheckEnabled`.

У WSL автоматичні оновлення Linux-дистрибутива не замінюють Windows Update —
обидва механізми потрібно налаштовувати окремо.

### 5. Блокування після невдалих входів

Скрипт перевіряє, чи використовується один із PAM-модулів:

- `pam_faillock.so`;
- `pam_tally2.so`.

Також шукається параметр `deny=N`, який визначає кількість невдалих спроб до
блокування облікового запису. Значення може бути в PAM-конфігурації або у
файлі `/etc/security/faillock.conf`.

Результат:

- `PASS`, якщо модуль налаштований і `deny` має додатне числове значення;
- `FAIL`, якщо модуль або `deny=N` відсутні;
- `SKIP`, якщо PAM-конфігурація недоступна.

У macOS скрипт пробує прочитати `maxFailedLoginAttempts` через `pwpolicy`.
Якщо параметр не показано, перевірка отримує `SKIP`.

## Статуси

Скрипт використовує три статуси:

- `PASS` — налаштування відповідає спрощеній перевірці;
- `FAIL` — налаштування відсутнє або не відповідає вимозі;
- `SKIP` — автоматична перевірка не дала надійного результату.

`SKIP` не означає, що все безпечно. Такий пункт потрібно перевірити вручну
або повторити запуск із достатніми правами.

## Рекомендації

Після кожного `FAIL` або `SKIP` скрипт виводить рекомендацію для поточної
платформи.

Якщо рекомендація містить команди, кожна команда показується на окремому
рядку:

```text
[FAIL] Фаєрвол UFW — ufw не встановлено
       Рекомендація:
         Установіть UFW і задайте базові правила:
         $ sudo apt update
         $ sudo apt install ufw
         $ sudo ufw default deny incoming
         $ sudo ufw default allow outgoing
         $ sudo ufw enable
```

Перед виконанням команд потрібно прочитати рекомендацію повністю. Не варто
сліпо копіювати команди на робочий сервер без розуміння їхнього впливу.

## Кольори у звіті

- `PASS` — зелений;
- `FAIL` — червоний;
- `SKIP` і заголовок рекомендації — жовтий;
- заголовки розділів — синій;
- команди в рекомендаціях — помаранчевий.

Кольори автоматично вимикаються, якщо вивід не спрямований у термінал. Їх
також можна вимкнути вручну:

```bash
NO_COLOR=1 ./cis_checklist.sh
```

## Як запустити

Перейдіть до папки домашнього завдання:

```bash
cd ~/Education/Cybersecurity-from-Scratch/HomeWork10
```

Додайте право на виконання:

```bash
chmod +x cis_checklist.sh
```

Звичайний запуск:

```bash
./cis_checklist.sh
```

Для повнішого доступу до захищених конфігурацій Linux:

```bash
sudo ./cis_checklist.sh
```

Навіть при запуску через `sudo` скрипт нічого не змінює в системі.

Записати звіт у файл:

```bash
NO_COLOR=1 ./cis_checklist.sh | tee cis_report.txt
```

## Код завершення

Скрипт повертає:

- `0`, якщо немає жодного `FAIL`;
- `1`, якщо знайдено хоча б один `FAIL`.

Перевірити код після запуску:

```bash
echo $?
```

Наявність `SKIP` не змінює код завершення на `1`, але такі перевірки потрібно
опрацювати вручну.

## Підсумок

Наприкінці скрипт показує:

- загальну кількість перевірок;
- кількість `PASS`, `FAIL` і `SKIP`;
- список усіх перевірок із їхніми статусами;
- загальний висновок;
- застереження про те, що це не офіційний CIS Benchmark.

Приклад:

```text
Підсумок
  Перевірок: 5 | PASS: 2 | FAIL: 1 | SKIP: 2

  Список перевірок:
    [PASS] Мінімальна довжина пароля
    [PASS] Фаєрвол UFW
    [FAIL] SSH: PermitRootLogin
    [SKIP] Автоматичні оновлення
    [SKIP] Блокування облікового запису

  Є налаштування, які не відповідають checklist.

  Примітка: Це не офіційний CIS Benchmark і не замінює повний аудит безпеки.
```

## Безпека під час виправлення

Особливо обережно потрібно змінювати:

- правила фаєрвола;
- конфігурацію SSH;
- PAM-файли та політику блокування.

Неправильне налаштування може заблокувати віддалений доступ або вхід усіх
користувачів. Перед змінами потрібно:

1. зробити резервну копію конфігурації;
2. не закривати поточну адміністративну сесію;
3. перевірити SSH через `sudo sshd -t`;
4. мати локальну або root-консоль для відновлення доступу;
5. перевіряти нове підключення перед завершенням старого.

## Перевірка якості скрипта

Скрипт використовує суворий режим Bash:

```bash
set -euo pipefail
```

Перевірка синтаксису:

```bash
bash -n cis_checklist.sh
```

Статичний аналіз:

```bash
shellcheck cis_checklist.sh
```
